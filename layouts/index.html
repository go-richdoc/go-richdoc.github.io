One document model,
and the formats that meet in it.

A document is worth one representation, not one per format. richdoc is that representation, and the rest of this organisation reads and writes it — so Markdown, reStructuredText, LaTeX, HTML, an EPUB, a FictionBook, an email and a CSV all meet in the middle instead of pairwise. Why a model at all {{ $n := len .Site.Params.repos }}{{ $formats := sub $n 1 }}

{{ $formats }} formats pairwise would be {{ mul $formats (sub $formats 1) }} converters.

Each would have to understand two formats at once, and every format added would need another for each one already there. Through a model it is two pieces of work per format — read it, write it — and a reader written once is a reader every writer can use. That is the whole architecture, and the arithmetic is why.

🔒

Closed interface sets

Every block and inline type carries an unexported marker method, so a converter can type-switch over all of them and the compiler knows when a case is missing. A model open to new node types would make every converter silently incomplete.

📦

Nothing but the tree

richdoc does no rendering, no parsing and no I/O. It is the one dependency every converter here shares, and the reason it can be shared is that it has nothing in it to disagree with.

🪆

A cell holds blocks

Not a line of text. reST's grid tables and HTML's <td> both allow a paragraph, a list and a table inside one cell, so a model whose cell is a string cannot carry what either format wrote.

🧾

RawBlock and RawInline

Format-specific passthrough, kept with the format's name beside it. It is what lets a LaTeX round trip return the macro nobody has modelled yet, instead of dropping it and calling the result lossless.

The two directions

Read it once, write it anywhere.

Markdown, reStructuredText and LaTeX read and write; HTML, EPUB, FictionBook, email and the data formats read. Which directions a module has is in its description below, because "converter" said of a one-way reader is the kind of claim that costs somebody an afternoon — and a module that only reads is not unfinished: an EPUB and a mailbox are sources, and writing one back is a job nobody has asked for.

The organisation

One module a format, and the model in the middle.

Each is its own module with its own release line, so a program takes the model and the one format it reads — never a stack of parsers it will not call.

What a round trip is for

Reversible is easy. Faithful is the work.

A converter that loses nothing it can represent is still wrong if it adds what the author never wrote — and that is the harder failure, because nothing is missing to notice.

🏷️

An anchor nobody wrote

goldmark can generate an id for every heading. markdown leaves that off, because the writer would then stamp a {#id} into source that never had one — a diff on every heading of every file, from a converter that was asked to preserve the document.

🔁

Delegate where a parser exists

CommonMark goes through goldmark and reST through go-docutils, because both are full, tested, pure-Go parsers. latex ships its own only because go-tex's tokenizer is internal — a compile API, not a parse tree.

📐

A heading's level is where it sat

FictionBook has no <h2>, only a section inside a section, and a title broken over several <p> for the line breaks. Three headings where a reader sees one is a document that navigates wrongly.

⛔

Said, when it is not kept

<sub> and <sup> have no node here, so FictionBook's text is kept and its position is not: losing the 2 of H2O to say so would be the worse trade. Every such decision is in the module's README, with the reason.

Where it runs

{{ len .Site.Params.targets }} build targets, and the suites run on amd64.

⛔ Said precisely, because the precise claim is cheap and the vague one is not true: every module here cross-builds for {{ $n := len .Site.Params.targets }}{{ range $i, $t := .Site.Params.targets }}{{ if $i }}{{ if eq $i (sub $n 1) }} and {{ else }}, {{ end }}{{ end }}{{ $t }}{{ end }}, and runs its tests on amd64 with the race detector. Where byte order is the risk rather than a worry — a ZIP's little-endian integers in go-ooxml — the suite runs under qemu on five more architectures, big-endian included. These libraries are a tree and a great deal of string handling, which is a different risk.

🌐

js/wasm is a target, not an afterthought

Nothing here opens a file: a converter takes bytes and returns bytes. An editor that converts a document in a browser tab needs no server, and nothing it reads leaves the machine.

🧮

CGO is off everywhere

Which is what makes js/wasm and the cross-builds possible at all, and why a binary that embeds any of these carries no C toolchain's worth of assumptions.

📚

Documentation of its own

The docs site is built by MkDocs and versioned with mike, so a reader can look at the release they are using rather than at main.

🖨️

And out the other side, a PDF

go-pdfkit composes a richdoc document, which is what makes .fb2 → PDF or .md → PDF a two-step with no format-specific code in between.

The model, {{ sub (len .Site.Params.repos) 1 }} formats, and one place where they meet.

A document read here can be written as Markdown, reStructuredText or LaTeX, laid out as a PDF by go-pdfkit, or edited in a browser tab — because all of them speak the same tree.
