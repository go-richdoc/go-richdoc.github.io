# go-richdoc landing

Hugo source for **<https://go-richdoc.github.io/>** — the landing page of the
[`go-richdoc`](https://github.com/go-richdoc) org.

Preview locally:

```sh
hugo server
```

Build:

```sh
hugo --gc --minify
```

The rendered site lives under `public/`, which is gitignored: GitHub Pages
builds it from this source (see `.github/workflows/pages.yml`).

## The design is not here

It comes from the shared Hugo module
[`go-fleettools/landingkit`](https://github.com/go-fleettools/landingkit),
pinned in `go.mod`. This landing used to be one of the drifted copies — it
carried a `brand.css` and a `theme.js` of its own, written before the kit
existed, and a 39-line layout that shared nothing with the rest of the fleet.

⛔ **`kit.go` is not optional.** A Hugo site has no Go code, so `go mod tidy`
finds nothing using the module and deletes the requirement — and the fleet's
Renovate presets run `gomodTidy` after every bump. The file exists only to be
seen by tidy; its build tag keeps it out of every build.

## The colours are read, not chosen

`landingkit brand static/img/logo.svg` derives `[params.brand]` from the
logo's own gradient. `go-richdoc` is in the **document family** — `go-odf`,
`go-ooxml`, `go-rtf`, `go-docutils` — and takes its `#4F46E5 → #1E1B4B`.
Backgrounds, surfaces, greys and borders belong to the shared sheet and cannot
be set here.

## ⛔ A green deploy is not a served page

go-ooxml's landing served Jekyll's rendering of its `README.md` while its
workflow built the Hugo site, uploaded it and reported success three times:
its Pages source was a **branch**, and that setting is in the API rather than
in any file. The last step of the deploy here fetches the live URL and fails
unless what comes back was generated by Hugo. `{{ hugo.Generator }}` in the
layout is the marker, so deleting that line breaks the deploy rather than the
page.

`pagescheck` in [go-fleettools](https://github.com/go-fleettools/fleettools)
is the fleet-wide version of the same question.

## ⛔ Targets built is not architectures tested

`[params.targets]` is the ten targets every module cross-builds for. The
suites run on **amd64**, with the race detector. The page says exactly that,
because go-ooxml's page said "six architectures, and the tests run on every
one" while they ran on one — it had been copied from go-pdfkit, where the
claim was true.
